# Forge v2.2.0

Forge 2.2.0 adds editable architecture templates and project-specific stacks for SwiftUI feature generation.

## Highlights

- Run interactive `forge init` to select an architecture and create a project configuration alongside editable templates. For automation, pass an architecture flag such as `forge init -mvvm`.
- Configure team-owned source and test roles in `.forge.yml`. Customize the generated Swift under `.templates/`, including views, model or store construction, data layers, previews, and tests.
- Use shared MVVM and MVI templates for forms and lists. Managed insertion points keep field bindings, state, actions, and initializer dependencies connected.
- Run `forge validate` to render enabled screen categories and identify missing or duplicate insertion points. For an unterminated tag, Forge identifies its opening line and shows the closing delimiter to add. Build generated output in the host project to verify team-specific Swift and dependencies.
- Preview generation and integration changes with `forge make --dry-run`. Configure the Xcode project and feature destination independently when the defaults do not fit.

## Adoption

Existing `.forge/templates/` overrides continue to work. Run `forge init --adopt` to activate the new templates, then transfer team edits and validate them. The original overrides remain available for reference. See the [template guide](../TEMPLATES.md) and [walkthrough](../WALKTHROUGH.md).

Xcode and Swift package integration support the project layouts documented in the README. Forge reports unsupported layouts before writing feature files. Teams own custom Swift and should compile generated fixtures against their host project's dependencies.
