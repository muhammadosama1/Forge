# Forge v2.0.0

Forge v2.0.0 makes feature generation configurable for different team conventions and adds safer integration with existing Swift packages.

## Highlights

- Use `forge init` to create `.forge.yml` with defaults for architecture, binding, testing, dependency injection, paths, and naming. CLI options can override project defaults.
- Choose Combine or Swift Concurrency and Observation bindings, XCTest or Swift Testing, and native composition or Factory dependency injection.
- Generate into an existing Swift package target with `--target`. Forge verifies the target, adds a test target when needed, and registers Factory dependencies for supported literal manifests.
- Run `make release-check VERSION=<version>` before publishing. It tests the release binary through user workflows and compiles a 45-case generated-code matrix.

## Breaking change

The Composable Architecture (`-tca`) is no longer supported. Projects using it should stay on the v1.x series or choose one of the five supported patterns: MVVM, MVI, VIPER, VIP, or MVP.

## Notes

- Existing package manifest editing supports literal target and dependency arrays with the standard `Sources/<Target>` layout. Forge reports unsupported manifests before writing feature files.
- Xcode project files still require manual source and test target registration. Add Factory to the Xcode project manually when using `di: factory`.
- Observation output requires iOS 17 or macOS 14. Swift Testing output requires iOS 16 or macOS 13.

## Verification

- 244 Swift unit tests passed.
- All 45 default generated packages and all 45 combined Factory, Observation, and Swift Testing packages built and passed their generated tests.
- Release smoke workflows passed, including local installation, configuration overrides, Swift Testing, Factory in an existing package, and error recovery.
